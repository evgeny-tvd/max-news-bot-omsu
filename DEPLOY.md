# 📖 DEPLOY.md — развёртывание max-news-bot-omsu

Инструкция для человека без опыта администрирования. Всё, что нужно, —
сервер или компьютер с Linux (или Windows/Mac с Docker) и ~10 минут времени.

---

## 1. Что понадобится

| Что | Где взять |
|---|---|
| Сервер/ПК с интернетом | VPS, Proxmox-контейнер, домашний ПК — что угодно |
| Docker | ставится автоматически по инструкции ниже |
| Токен бота MAX | создаётся в MAX (шаг 2) |
| Канал MAX | создаётся в MAX (шаг 3) |
| VK-паблик | ваш паблик; сервисный ключ — шаг 4 |

---

## 2. Создайте бота в MAX

1. Откройте мессенджер MAX.
2. Создайте бота (в приложении MAX: раздел создания ботов / чат с платформой ботов —
   у каждого бота есть свой токен).
3. Скопируйте **токен** — он понадобится при установке.

> Токен — это секрет. Никому его не показывайте: кто знает токен — управляет ботом.

## 3. Создайте канал и добавьте бота

1. В MAX создайте **канал** (например, «Новости города»).
2. Добавьте в канал вашего бота (как участника/администратора).
3. Напишите боту в этот канал: `/start` — он ответит:
   ```
   Привет! Я бот новостей 🤖
   📢 Этот чат: -123456789012345
   ```
   Число после «Этот чат:» — это **ID канала**. Запишите его (со знаком «-»).

## 4. VK: сервисный ключ (обязательно)

VK-паблик — **основной источник** бота. Для чтения стены нужен **сервисный ключ
приложения VK**. Получение бесплатно и занимает ~5 минут.

### Пошагово

1. Откройте **https://dev.vk.ru** и войдите под аккаунтом VK, с которого
   управляете пабликом (подойдёт обычный личный аккаунт администратора).
2. Нажмите **«Создать приложение»** (или «Создать мини-приложение»):
   - **Название** — любое, например «Новостной репостер»;
   - **Тип/платформа** — Mini Apps (VK Mini App);
   - Подтвердите создание.
3. В открывшемся кабинете приложения перейдите в раздел
   **«Разработка» → «Ключи доступа»**
   (в некоторых версиях интерфейса раздел называется «Настройки» → «Ключи доступа»).
4. В блоке **«Сервисный ключ доступа»** нажмите «Показать» и скопируйте ключ.
5. Вставьте ключ при установке — мастер спросит его (переменная `VK_TOKEN` в `.env`).

### ⚠️ Важные нюансы

| Нюанс | Что делать |
|---|---|
| **Нужен именно сервисный ключ приложения** | «Ключ сообщества» (access token сообщества) **НЕ подходит** — VK вернёт ошибку 27. Если видите ошибку 27 — вы скопировали не тот ключ |
| Сервисный ключ видит только открытые данные | посты вашего паблика прочитает, публиковать ничего не может — безопасно |
| Ключ — секрет | хранится в `.env` (права 600), в git не попадает. Никому не показывайте |
| Ключ засветился/перестал работать | перевыпустите его в dev.vk.ru (кнопка перевыпуска сервисного ключа), обновите `.env` и выполните `docker compose up -d --force-recreate` |
| Паблик закрытый (приватный) | сервисный ключ не прочитает закрытую стену — паблик должен быть открытым |

## 5. Установка

Подключитесь к серверу по SSH и выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/evgeny-tvd/max-news-bot-omsu/main/install.sh)
```

> ⚠️ Не заменяйте на `curl … | bash`: в этом случае мастер не сможет
> прочитать ваши ответы (stdin занят скриптом). Если `bash <(…)` у вас
> не работает — скачайте файл и запустите:
> `curl -fsSL https://raw.githubusercontent.com/evgeny-tvd/max-news-bot-omsu/main/install.sh -o install.sh && bash install.sh`

Если Docker не установлен — скрипт подскажет:
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# перезайдите в SSH и повторите установку
```

Мастер задаст вопросы:
- **Токен бота** — из шага 2;
- **ID канала** — из шага 3;
- **VK-паблик** — адрес без `vk.com/` (по умолчанию `gorodtavda`, укажите свой);
- **Сервисный ключ VK** — из шага 4 (обязателен);
- **Канал предупреждений** — ID публичного канала MAX (встроен по умолчанию:
  РСЧС Свердловской области; если вы из другого региона — укажите свой; можно оставить как есть);
- **Интервал опроса** — по умолчанию 60 секунд.

## 6. Проверка

```bash
docker compose ps          # STATUS: Up / healthy
docker compose logs -f     # «Новых постов нет…» — всё работает
```

> **Важно про первый запуск:** бот запоминает последний пост/сообщение источника
> и **не публикует старые**. Новые новости начнут приходить после их публикации
> в источнике. Это сделано специально, чтобы канал не засорялся архивом.

## 7. Частые вопросы

**Бот не отвечает на /start?**
Добавьте бота в канал правильно (шаг 3), подождите 1–2 минуты после запуска.
Смотрите логи: `docker compose logs -f`.

**Почему /news_now и /rsch_now «не работают» из лички?**
Это защита: управляющие команды пишут в ваш канал, поэтому по умолчанию они
работают **только из самого канала** (напишите команду прямо в канале, где бот
состоит). Если нужно запускать из личных чатов — добавьте их ID в `ADMIN_CHAT_IDS`
в `.env` (через запятую) и перезапустите: `docker compose up -d --force-recreate`.

**VK не отдаёт посты / в логах «VK API error» с кодом 27?**
Вы скопировали не тот ключ: нужен **сервисный ключ приложения** из dev.vk.ru
(шаг 4), а не ключ сообщества. Перевыпустите/скопируйте правильный, обновите
`.env` и перезапустите: `docker compose up -d --force-recreate`.

**Хочу добавить второй источник позже.**
Отредактируйте `.env` (он в той же папке, что и docker-compose.yml):
```bash
nano .env        # добавьте VK_DOMAIN=… / VK_TOKEN=… / RSCH_CHAT_ID=…
docker compose up -d --force-recreate
```

**Как обновить бота?**
```bash
docker compose pull && docker compose up -d
```

**Где хранится состояние (какие посты уже отправлены)?**
В папке `state/` рядом с docker-compose.yml. Удалять не нужно — иначе бот
«забудет» отправленное.

**Хочу мгновенные команды (webhook) — у меня есть домен.**
В `.env` задайте:
```
POLLING=false
WEBHOOK_URL=https://ваш-домен/webhook
WEBHOOK_SECRET=<длинный случайный набор символов>
```
Направьте домен на порт 8080 контейнера (nginx/Caddy с HTTPS-сертификатом).
Long Polling при этом должен быть выключен: MAX не допускает оба режима сразу.

## Не работает? Полезные команды

```bash
docker compose logs --tail=50      # последние ошибки
docker compose restart             # перезапуск
docker compose down && docker compose up -d   # полный перезапуск
```

Если ошибка непонятна — скопируйте вывод `docker compose logs --tail=50` и
покажите тому, кто настраивает бота.
